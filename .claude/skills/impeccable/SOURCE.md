## Role In This Project

The main UI skill. Every screen is checked with it before its spec is done. `context/ui-context.md` ("How Screens Are Made") says when.

- **Mode:** Operate (app UI: scanability, consistency and native Mac expectations come first).
- **Context it reads:** `PRODUCT.md` and `DESIGN.md` at the project root. Both are thin summaries generated from `context/project-overview.md` and `context/ui-context.md`. Those files win wherever they differ, and are updated first.

## Project Rules For Using It

These win over `SKILL.md` where they differ.

1. **No launcher.** Do not run `scripts/impeccable` (it downloads and runs a native binary that was not read). Use the skill's "Launcher unavailable" path every time: say "Context loading did not run; I'll read the existing project context directly", then read `PRODUCT.md` and `DESIGN.md`, and `reference/craft-floor.md` before any UI edit. Turning the launcher on is the author's decision, recorded in `context/decisions/ui-and-wireframe-skills.md`.
2. **Never use** `live` or `generate` (live mode can run `claude` with permissions bypassed), `hooks on`, `pin`, `foundations`, or `doctor` repairs.
3. **Never run** `init` or `document`: they would overwrite `PRODUCT.md` and `DESIGN.md`. Those two files are regenerated by hand from `context/` when it changes.
4. **Use:** `critique` and `audit` on every screen before its spec is done, fixing P0 and P1 findings. `polish` before a phase with screens is demoed. `layout`, `typeset`, `quieter`, `clarify` and `harden` when a screen needs them.
5. **Invented data only** in anything it looks at or writes. No client screenshots.
6. **Updating:** read the changes to `.claude/skills/impeccable/` in any newer commit in full before copying it, then record the new commit here (risk K4).
